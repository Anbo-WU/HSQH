# 金融业务运营自动化工具集

这是一组从真实部门工作需求中沉淀出的 Python 自动化工具，覆盖业务、交易、结算、开户和合规等日常运营场景。项目主要处理 Word、PDF 和 Excel 文件，用于减少批量计算、文件命名、信息提取、表格匹配及格式整理等重复工作。

仓库中的示例文件已对客户信息作脱敏处理。代码中的表格位置、评分规则、文件名规则和目录约定均来自特定业务流程，使用前请结合所在机构的最新制度、模板和系统导出格式进行复核。

## 功能概览

| 岗位/模块 | 工具 | 主要用途 | 主要输入与输出 |
| --- | --- | --- | --- |
| 业务 | `填充业务记录.py` | 批量提取“保险+期货”立项申请表中的项目要素，统一期限、比例、期权结构等格式并汇总 | 多批次立项申请表 → `业务记录.xlsx` |
| 交易 | `确认书扫描重命名.py` | 使用 macOS 本地 OCR 识别确认书首页交易编号，批量生成标准文件名 | 扫描版 PDF → 重命名后的 PDF |
| 交易 | `确认书入登记表.py` | 递归提取确认书文件名，自然排序后写入合同章登记表，并按模板自动分页 | PDF 文件名 → `登记表模版.xls` |
| 结算 | `settleUpdate.py` | 批量调整远期了结记录的列结构、字段名称、收益方向与合计行，并生成规范文件名 | HTML 格式 `.xls` → 新版 `.xls` |
| 开户 | `分数提取.py` | 从 Word/PDF 风险测评问卷中提取客户名称和 20 道题答案 | `.doc`/`.docx`/`.pdf` → `分数统计.xlsx` |
| 开户 | `等级计算.py` | 按内置评分表计算问卷总分及 C1～C5 风险承受能力等级 | `分数统计.xlsx` → 回写总分和等级 |
| 合规 | `fill_customer_nature.py` | 按客户名称匹配参考表，批量补充客户性质，同时保留已有结果 | `A.xlsx` + `B.xlsx` → 更新 `A.xlsx` |

这些工具以本地文件处理为主，不会主动向外部服务上传业务数据。两个 OCR 场景调用的是 macOS 自带的 PDFKit 与 Vision 框架。

## 运行环境

- Python 3.10 或更高版本
- Excel 或 WPS Office，用于查看和人工复核处理结果
- `openpyxl`，用于 `.xlsx` 文件处理
- `xlrd`、`xlwt`、`xlutils`，仅用于交易登记表的旧版 `.xls` 模板
- macOS 及 Apple Command Line Tools，仅在读取扫描版 PDF 或执行确认书 OCR 重命名时需要

建议在虚拟环境中安装依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install openpyxl xlrd==1.2.0 xlwt==1.3.0 xlutils==2.0.0
```

如需使用 PDF OCR，请先确认系统可以调用 Swift 编译器：

```bash
xcode-select --install
swiftc --version
```

## 使用方法

### 1. 业务：汇总立项申请表

将申请表分别放入 `业务/202611`、`业务/202612` 和 `业务/202613`。脚本会按批次和文件名自然排序，提取 15 个业务字段，从 `业务记录.xlsx` 第 3 行开始写入，并从序号 23 起连续编号。

先预览提取结果：

```bash
python3 业务/填充业务记录.py --preview
```

确认后更新默认汇总表：

```bash
python3 业务/填充业务记录.py
```

也可以指定工作目录和新的输出文件，保留原模板：

```bash
python3 业务/填充业务记录.py \
  --root /path/to/project_folder \
  --output /path/to/output/业务记录_已更新.xlsx
```

脚本会兼容部分不同版本的字段行位置，并统一处理产品周期、采价周期、是否保底、百分比和金额格式。默认模式会更新 `业务记录.xlsx`；运行前请关闭 Excel/WPS 中已打开的同名文件。

### 2. 交易：扫描确认书批量重命名

将待处理 PDF 放入 `交易/确认书扫描` 及其子目录。脚本使用 macOS Vision OCR 识别每份文件首页的交易编号，并根据编号中的日期生成标准文件名。

```bash
# 仅识别并展示改名计划
python3 交易/确认书扫描重命名.py --preview

# 执行批量重命名
python3 交易/确认书扫描重命名.py
```

正式改名前，脚本会统一检查未识别编号、多个候选编号、重名及目标文件冲突。执行时采用两阶段重命名；如中途失败，会尽量恢复原文件名。PDF 内容不会被修改。

### 3. 交易：生成合同章登记表

将确认书 PDF 放入 `交易/确认书文件`，文件可以分层存放。脚本会递归收集文件名、删除约定的固定文字，并以自然顺序填入 `登记表模版.xls` 的 B5:B27。

```bash
# 查看排序及提取结果
python3 交易/确认书入登记表.py --preview

# 写入登记表
python3 交易/确认书入登记表.py
```

每页最多写入 23 条记录。超过一页时，脚本会复制完整模板、保留样式和页尾说明并插入手动分页。该工具会原地更新 `登记表模版.xls`，建议先保留模板副本。

### 4. 结算：转换远期了结记录

将系统导出的文件放入 `结算/老版本`。这里的 `.xls` 实际应为 UTF-8 编码的 HTML 表格，而不是传统二进制 Excel 工作簿。

```bash
python3 结算/settleUpdate.py
```

指定其他输入、输出目录：

```bash
python3 结算/settleUpdate.py \
  --input-dir /path/to/old_files \
  --output-dir /path/to/new_files
```

脚本会批量执行以下处理：

- 删除不再需要的列并更新“客户了解远期收益”字段；
- 将收益调整为客户视角，同时保留原小数位；
- 校验相关合计，如有差异则按既定规则调整；
- 添加合计行，并按客户简称、业务编号和源文件名生成新文件名；
- 单个文件失败时记录原因，继续处理其余文件。

转换结果默认写入 `结算/新版本`。同名结果可能被覆盖，重新执行前请确认输出目录中的文件是否需要保留。

### 5. 开户：提取问卷并计算风险等级

将机构交易者风险测评问卷放入 `开户/问卷`。支持 `.doc`、`.docx` 和 `.pdf`；扫描版 PDF 的 OCR 仅支持 macOS。

第一步，提取客户名称及 20 道题答案：

```bash
python3 开户/分数提取.py --preview
python3 开户/分数提取.py
```

也可以指定输入目录和目标表：

```bash
python3 开户/分数提取.py \
  --input-dir /path/to/questionnaires \
  --output /path/to/分数统计.xlsx
```

第二步，计算总分及风险承受能力等级：

```bash
python3 开户/等级计算.py --preview
python3 开户/等级计算.py
```

若需处理其他工作簿：

```bash
python3 开户/等级计算.py --workbook /path/to/分数统计.xlsx
```

提取和评分均采用“先完整校验、后统一写入”的方式：任一问卷缺题、答案无效、表头不一致或客户数据不完整时，脚本会停止并避免写入部分结果。保存 Excel 时使用同目录临时文件替换，降低工作簿损坏风险。

> 风险等级阈值和逐题分值已直接写入 `等级计算.py`。监管要求、问卷版本或公司制度变化后，应先更新并复核评分规则。

### 6. 合规：补充客户性质

准备两个工作簿并放入 `合规` 目录：

- `A.xlsx`：待补充文件，B 列为客户名称，C 列为客户性质；
- `B.xlsx`：参考文件，B 列为客户名称，D 列为客户性质。

执行：

```bash
python3 合规/fill_customer_nature.py
```

脚本按去除空格并转为小写后的客户名称精确匹配，只填充 `A.xlsx` 中 C 列为空的记录，不覆盖已有值。当前版本会直接保存至 `A.xlsx`，且没有预览参数，运行前务必备份源文件。

## 数据安全与使用建议

本项目面向可能涉及客户资料、交易记录和内部审批信息的文件。即使代码全部在本地执行，也建议遵循以下原则：

1. 先复制少量脱敏文件进行预览和验证，再处理完整批次。
2. 对会原地写入或重命名的工具保留备份，并在运行时关闭 Excel、WPS 或 Word。
3. 不要将真实客户资料、证件号码、交易数据、内部人员信息或未公开模板提交到 Git 仓库。
4. Office 文件可能在文档属性、批注、隐藏工作表、外部链接和修订记录中保留作者或历史信息；公开前应单独检查并清理元数据。
5. OCR、文件名识别和跨表匹配结果必须经过人工复核，不应把自动处理结果视为最终业务审批结论。
6. 建议将真实输入目录和生成结果加入 `.gitignore`，仓库中只保留最小化、不可反推真实业务的测试样例。

## 已知限制

- 多数工具依赖固定的文件名、列号、表头或模板结构；源系统和模板升级后可能需要同步修改代码。
- PDF OCR 依赖 macOS Vision，其他操作系统应先将扫描件转换为可搜索 PDF 或 DOCX。
- `分数提取.py` 只读取 `问卷` 目录当前层的文件，不递归子目录。
- `填充业务记录.py` 默认要求三个批次目录全部存在，并使用固定的起始序号和写入行。
- `fill_customer_nature.py` 当前使用固定文件名和列位置，且不会生成未匹配明细文件。
- 项目暂未提供自动化测试；每次调整模板或业务规则后，应使用脱敏样例执行回归验证。
