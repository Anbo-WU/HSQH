# HSQH 金融业务运营自动化工具集

> 当前版本：**V2.0**
>
> 更新时间：**2026-08-27**

HSQH 是一组从实际部门工作流程中沉淀出的 Python 自动化工具，覆盖业务、交易、结算、开户和合规等运营场景。项目主要处理 Word、PDF 和 Excel 文件，用于减少批量计算、文件检查、OCR 识别、文件命名、表格匹配、格式转换及交付归档等重复工作。

V2.0 对交易和结算模块进行了工作流级重构：交易模块现在提供按人员、日期和批次运行的统一入口；结算模块拆分为数据筛选和格式改版两个阶段，并补充了校验、归档与交付机制。

仓库中的示例文件已对客户信息作脱敏处理。代码中的表格位置、评分规则、文件名规则和目录约定均来自特定业务流程，使用前请结合所在机构的最新制度、模板和系统导出格式进行复核。

## V2.0 主要更新

- 重构交易确认书流程，新增统一入口 `交易/main.py`，支持 LuX、Tan、Zhang、LuT 四个人员目录。
- 将交易流程拆分为盖章前 A 流程（预检查、登记表生成、PDF 合并）和盖章后 B 流程（整本扫描件拆分、OCR 重命名）。
- 新增日期与批次管理、断点续跑判断、桌面交付副本、ZIP 打包及 `运行记录.json` 日志。
- 预检查新增重名、复制件、SHA-256 内容重复和命名格式异常检查。
- 登记表支持 PDF、DOC、DOCX 混合输入、自然排序、每页 23 条和自动扩页。
- 合并工具支持通过 WPS 将 Word 转为 PDF；每份确认书合并前会调整为偶数页：奇数页文件的尾页为空白时删除，否则补入同尺寸空白页。
- 盖章后整本扫描件可按期权 4 页、远期 2 页的固定结构 OCR 拆分，并校验标题、交易编号、页数、下一份首页及总份数。
- 重构结算流程：`split.py` 按累计远期到期表拆分当日导出数据，`update.py` 完成格式改版、收益方向转换、金额校验和交付打包。
- 结算旧结果会先压缩并校验，再清理输出目录；新版本处理完成后自动生成桌面交付 ZIP。

## 功能概览

- **业务**：从“保险+期货”立项申请表提取项目字段并汇总至 `业务记录.xlsx`。
- **交易**：完成确认书预检查、登记表生成、Word 转 PDF、批量合并、盖章扫描件拆分、OCR 重命名及交付打包。
- **结算**：按累计到期编号拆分远期了结记录，转换新版列结构，校验客户收益并归档交付。
- **开户**：从 Word/PDF 风险测评问卷中提取答案，并计算总分及 C1～C5 风险等级。
- **合规**：按客户名称匹配参考表，批量补充客户性质，同时保留已有结果。

所有核心工具以本地文件处理为主，不会主动向外部服务上传业务数据。OCR 使用 macOS 自带的 PDFKit 与 Vision 框架。

## 运行环境

- Python 3.10 或更高版本。
- macOS，交易 OCR、扫描件拆分、问卷 PDF OCR 及 WPS Word 转 PDF 功能需要使用。
- WPS Office，交易确认书中包含 `.doc` 或 `.docx` 时用于转换 PDF；首次运行可能需要授予自动化和辅助功能权限。
- Excel 或 WPS Office，用于查看和人工复核结果。
- Apple Command Line Tools，用于编译 PDFKit/Vision 辅助程序。

建议在虚拟环境中安装依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install openpyxl xlrd==1.2.0 xlwt==1.3.0 xlutils==2.0.0 pypdf
```

其中 `pypdf` 是 PDF 合并在无法使用 macOS PDFKit 时的备用依赖。独立运行带电子签名的登记表脚本时，可额外安装 `Pillow`；macOS 下也可使用系统自带的 `sips`。

确认 Swift 编译环境：

```bash
xcode-select --install
swiftc --version
```

## 使用方法

### 1. 交易：统一工作流（V2.0）

交易模块推荐始终从仓库根目录运行 `交易/main.py`。不传人员和流程参数时，程序会在终端中交互选择。

```bash
python3 交易/main.py
```

也可以直接指定人员和流程：

```bash
python3 交易/main.py --LuX --A
python3 交易/main.py --LuX --B
```

#### A 流程：盖章前处理

先将本批确认书放入对应人员的 `确认书文件` 目录，支持递归子目录中的 `.pdf`、`.doc` 和 `.docx`。建议文件名使用以下格式：

```text
公司名称_商品交易确认书_【HFSY】四位编号-JY或FWJY-八位日期两位流水号.pdf
```

运行：

```bash
# 交互处理预检查异常
python3 交易/main.py --teacher LuX --flow A

# 只预览，不生成登记表、转换 Word 或合并 PDF
python3 交易/main.py --teacher LuX --flow A --dry-run

# 非交互运行：发现预检查异常立即停止
python3 交易/main.py --teacher LuX --flow A --on-issue stop
```

A 流程依次执行：

1. `precheck.py`：递归检查 PDF 的完全同名、常见复制件后缀、SHA-256 内容重复及命名异常；只报告，不自动删除或修改文件。
2. `registration.py`：自然排序确认书，生成登记表；每页最多 23 条，超出时复制完整模板并自动分页。
3. `merge.py`：通过 WPS 转换需要处理的 Word 文件，并合并全部 PDF。每份确认书在合并前都会校正为偶数页，避免双面打印时不同确认书相互串页。

输出会同时保存在人员目录和当前用户桌面：

```text
登记表_<人员>_<YYYYMMDD>_<批次>.xls
确认书合并_<人员>_<YYYYMMDD>_<批次>.pdf
```

同一天再次运行时会自动选择未完成批次继续处理，否则创建下一个批次。也可以手动指定：

```bash
python3 交易/main.py --Tan --A --task-date 20260827 --batch 2
```

#### B 流程：盖章后处理

将盖章后的整本扫描件放到对应人员的 `确认书扫描` 目录，并以当天月日命名，例如 2026-08-27 对应：

```text
交易/LuX/确认书扫描/0827.pdf
```

随后运行：

```bash
python3 交易/main.py --LuX --B
```

B 流程默认关联该人员最近一个已完成的 A 批次，也可以通过 `--task-date` 和 `--batch` 明确指定已完成批次。流程会：

1. 统计原始确认书数量作为拆分结果的硬性校验值。
2. 对整本扫描件逐页 OCR，按期权确认书 4 页、远期确认书 2 页拆分。
3. 校验标题、交易编号、页数边界、下一份首页和总份数，并生成 `拆分记录.json`。
4. 对拆分后的每份 PDF 再次识别首页交易编号，生成标准文件名。
5. 将结果目录压缩到桌面，压缩包不包含内部的 `拆分记录.json`。

默认输出示例：

```text
交易/LuX/确认书扫描/扫描件_0827_LuX_01/
~/Desktop/扫描件_0827_LuX_01.zip
```

如果拆分出现异常，交互模式可选择 `stop`、`resplit` 或 `continue`。非交互任务建议显式使用 `--on-split-issue stop`。`--dry-run` 会执行 OCR 并预览拆分计划，但不会生成拆分 PDF、重命名文件或创建 ZIP。

每次 A/B 流程都会向对应人员的 `运行记录.json` 追加状态、耗时、参数、路径和各步骤结果；包括成功、失败、停止、中断和预览运行。

各子脚本仍可独立运行，使用 `python3 交易/code/<脚本名> --help` 查看参数，但日常业务建议使用统一入口，避免遗漏批次、校验或交付步骤。

### 2. 结算：拆分与改版（V2.0）

结算业务母目录需要包含：

```text
结算/
├── 累计远期到期/累计远期到期MMDD.xls
├── 远期镒链导出/远期了结记录导出YYYYMMDD.xls
├── 老版本/
└── 新版本/
```

`累计远期到期` 中的文件应为二进制 `.xls`；`远期镒链导出` 和后续生成的远期了结记录虽然扩展名为 `.xls`，实际是 HTML 表格。

第一步，根据累计到期表 C 列编号拆分当日导出表：

```bash
# 先检查匹配结果，不归档、不清理、不写入
python3 结算/split.py --date 20260827 --base-dir 结算 --dry-run

# 正式生成老版本拆分文件
python3 结算/split.py --date 20260827 --base-dir 结算
```

`split.py` 会检查累计表 C/E 列是否一致，以 C 列编号匹配导出表 AC 列，按累计表顺序生成 `远期了结记录导出01.xls` 等文件。正式写入前，已有 `老版本` 内容会先保存到 `结算/archive/老版本YYYYMMDD批次NN.zip`，压缩包通过完整性校验后才清空原目录。

第二步，将老版本批量转换为新版本并校验：

```bash
python3 结算/update.py --date 20260827 --base-dir 结算
```

`update.py` 会执行以下处理：

- 删除 C、F、X、Y、Z、AA、AB、AD 列，将 U 列标题改为“客户了结远期收益”。
- 将 U 列收益切换为客户视角并保留原小数位。
- 汇总 O、U、V 列；O/V 合计不一致时按规则使用 V 列覆盖 O 列。
- 添加合计行，并按客户简称、业务编号和源文件名生成新文件名。
- 将新版本最终 S 列客户收益与累计到期表 I 列公司金额进行反向校验。
- 先归档已有 `新版本` 内容，再处理本批文件；最后在桌面生成 `新版本YYYYMMDD批次NN.zip`。

如需使用仓库外的业务目录，`split.py` 可指定 `--output-dir` 和 `--archive-dir`；`update.py` 可指定 `--input-dir`、`--output-dir`、`--archive-dir` 和 `--desktop-dir`。执行 `python3 结算/split.py --help` 或 `python3 结算/update.py --help` 查看完整参数。

### 3. 业务：汇总立项申请表

将申请表分别放入 `业务/202611`、`业务/202612` 和 `业务/202613`。脚本会按批次和文件名自然排序，提取 15 个业务字段，从 `业务记录.xlsx` 第 3 行开始写入，并从序号 23 起连续编号。

```bash
# 预览
python3 业务/填充业务记录.py --preview

# 更新默认汇总表
python3 业务/填充业务记录.py

# 指定输入母目录和输出文件
python3 业务/填充业务记录.py \
  --root /path/to/project_folder \
  --output /path/to/output/业务记录_已更新.xlsx
```

脚本兼容部分不同版本的字段行位置，并统一处理产品周期、采价周期、是否保底、百分比和金额格式。默认会更新 `业务记录.xlsx`，运行前请关闭 Excel/WPS 中已打开的同名文件。

### 4. 开户：提取问卷并计算风险等级

将机构交易者风险测评问卷放入 `开户/问卷`。支持 `.doc`、`.docx` 和 `.pdf`；扫描版 PDF OCR 需要 macOS。

```bash
# 第一步：提取客户名称和 20 道题答案
python3 开户/分数提取.py --preview
python3 开户/分数提取.py

# 第二步：计算总分和风险等级
python3 开户/等级计算.py --preview
python3 开户/等级计算.py
```

也可以指定其他输入和输出：

```bash
python3 开户/分数提取.py \
  --input-dir /path/to/questionnaires \
  --output /path/to/分数统计.xlsx

python3 开户/等级计算.py \
  --workbook /path/to/分数统计.xlsx
```

提取和评分采用“先完整校验、后统一写入”：任一问卷缺题、答案无效、表头不一致或客户数据不完整时，程序会停止，避免写入部分结果。

> 风险等级阈值和逐题分值直接写在 `等级计算.py` 中。监管要求、问卷版本或公司制度变化后，应先更新并复核评分规则。

### 5. 合规：补充客户性质

准备两个工作簿：

- `A.xlsx`：待补充文件，B 列为客户名称，C 列为客户性质。
- `B.xlsx`：参考文件，B 列为客户名称，D 列为客户性质。

将文件放入 `合规` 目录、仓库根目录或当前工作目录后执行：

```bash
python3 合规/fill_customer_nature.py
```

脚本按去除空格并转为小写后的客户名称精确匹配，只填充 `A.xlsx` 中 C 列为空的记录，不覆盖已有值。当前脚本会直接保存至 `A.xlsx`，且没有预览参数，运行前务必备份源文件。

## 数据安全与使用建议

1. 先使用少量脱敏文件和 `--preview`/`--dry-run` 验证，再处理完整批次。
2. 对会原地写入、清理目录或重命名的工具保留独立备份；归档 ZIP 不能替代正式备份制度。
3. 运行时关闭 Excel、WPS 或 Word 中已打开的同名输入/输出文件。
4. 不要将真实客户资料、证件号码、交易数据、内部人员信息或未公开模板提交到 Git 仓库。
5. Office 文件可能在文档属性、批注、隐藏工作表、外部链接和修订记录中保留历史信息，公开前应单独清理元数据。
6. OCR、文件名识别、金额校验和跨表匹配结果必须经过人工复核，不应视为最终业务审批结论。
7. 建议将真实输入目录、运行日志、签名图和生成结果加入 `.gitignore`，仓库中只保留最小化且不可反推真实业务的测试样例。

## 已知限制

- 多数工具依赖固定的文件名、列号、表头和模板结构；源系统或模板升级后需要同步修改并回归验证。
- 交易 B 流程只支持期权 4 页、远期 2 页的固定确认书结构，并要求整本扫描件按当天 `MMDD.pdf` 命名。
- 交易 Word 转 PDF 依赖 macOS 上的 WPS 界面自动化；WPS 版本或界面语言变化可能影响转换。
- macOS PDFKit 不可用时，合并功能需要 `pypdf`；OCR 拆分和 OCR 重命名仍只能在 macOS 上运行。
- `分数提取.py` 只读取 `问卷` 目录当前层的文件，不递归子目录。
- `填充业务记录.py` 默认要求 202611、202612、202613 三个批次目录均存在，并使用固定起始序号和写入行。
- `fill_customer_nature.py` 使用固定文件名和列位置，不生成未匹配明细文件。
- 项目暂未提供自动化测试；每次调整模板、OCR 规则或业务规则后，应使用脱敏样例执行回归验证。
